# API Contract: Campus Equipment Booking API

**Production Base URL:**
```text
https://campus-equipment-booking-api.nutjon.workers.dev/api
```

*(Note: Routes are also mounted at the root path `/` for maximum client compatibility).*

---

## 1. Error Response Format

Every error response strictly returns a JSON object with a single `error` string field:

```json
{
  "error": "A clear message describing the error"
}
```

### Standard HTTP Status Codes

| Status Code | Meaning | When Returned |
|:---:|---|---|
| **`200 OK`** | Success | Successful read or update operation |
| **`201 Created`** | Created | Successful resource creation (`POST /bookings`) |
| **`204 No Content`** | No Content | Successful deletion (`DELETE /bookings/:id`) with empty body |
| **`400 Bad Request`** | Client Error | Missing or invalid required fields, unparseable date strings, `startAt >= endAt`, or empty update payload |
| **`404 Not Found`** | Resource Not Found | Target booking `:id` not found, or referenced `equipmentId` does not exist |
| **`409 Conflict`** | Conflict | Booking time interval overlaps with an existing booking for the same equipment |

## 3. Bookings Resource

### Booking Field Specifications

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique identifier generated by the server (UUID) |
| `equipmentId` | `string` | ID of the equipment being reserved (e.g., `"eq-1"`) |
| `borrowerName` | `string` | Full name of the student or faculty member |
| `startAt` | `string` | ISO 8601 UTC timestamp of reservation start |
| `endAt` | `string` | ISO 8601 UTC timestamp of reservation end |
| `purpose` | `string` | Intended purpose of use |

---

### `GET /bookings`
* **Purpose:** List all scheduled equipment bookings ordered chronologically by `startAt`.
* **Request Body:** None
* **Success Status:** `200 OK`
* **Response Example:**
  ```json
  [
    {
      "id": "ac987ead-cd6b-4e6d-9eae-360aa127dcba",
      "equipmentId": "eq-1",
      "borrowerName": "Somchai Jaidee",
      "startAt": "2026-10-20T09:00:00.000Z",
      "endAt": "2026-10-20T11:00:00.000Z",
      "purpose": "Class presentation"
    }
  ]
  ```

---

### `GET /bookings/:id`
* **Purpose:** Retrieve a single booking by its unique ID.
* **Request Body:** None
* **Success Status:** `200 OK`
* **Response Example:**
  ```json
  {
    "id": "ac987ead-cd6b-4e6d-9eae-360aa127dcba",
    "equipmentId": "eq-1",
    "borrowerName": "Somchai Jaidee",
    "startAt": "2026-10-20T09:00:00.000Z",
    "endAt": "2026-10-20T11:00:00.000Z",
    "purpose": "Class presentation"
  }
  ```
* **Error Status:**
  * `404 Not Found`:
    ```json
    { "error": "Booking not found" }
    ```

---

### `POST /bookings`
* **Purpose:** Create a new equipment booking.
* **Request Headers:** `Content-Type: application/json`
* **Required Payload Fields:** All fields are required (`equipmentId`, `borrowerName`, `startAt`, `endAt`, `purpose`).
* **Request Example:**
  ```json
  {
    "equipmentId": "eq-1",
    "borrowerName": "Somchai Jaidee",
    "startAt": "2026-10-20T09:00:00.000Z",
    "endAt": "2026-10-20T11:00:00.000Z",
    "purpose": "Class presentation"
  }
  ```
* **Success Status:** `201 Created`
* **Response Example:**
  ```json
  {
    "id": "ac987ead-cd6b-4e6d-9eae-360aa127dcba",
    "equipmentId": "eq-1",
    "borrowerName": "Somchai Jaidee",
    "startAt": "2026-10-20T09:00:00.000Z",
    "endAt": "2026-10-20T11:00:00.000Z",
    "purpose": "Class presentation"
  }
  ```
* **Validation & Error Responses:**
  * `400 Bad Request` (Missing/blank required fields):
    ```json
    { "error": "Missing or invalid required fields" }
    ```
  * `400 Bad Request` (Invalid date format):
    ```json
    { "error": "startAt and endAt must be valid date strings" }
    ```
  * `400 Bad Request` (Start time not before end time):
    ```json
    { "error": "startAt must be before endAt" }
    ```
  * `404 Not Found` (Equipment does not exist):
    ```json
    { "error": "Equipment not found" }
    ```
  * `409 Conflict` (Booking overlaps with existing schedule on same equipment):
    ```json
    { "error": "Booking time conflicts with an existing booking" }
    ```

---

### `PATCH /bookings/:id`
* **Purpose:** Partially update an existing booking.
* **Request Headers:** `Content-Type: application/json`
* **Allowed Payload Fields (At least one must be provided):** `equipmentId`, `borrowerName`, `startAt`, `endAt`, `purpose`.
* **Request Example:**
  ```json
  {
    "borrowerName": "Somchai Jaidee",
    "startAt": "2026-10-20T12:00:00.000Z",
    "endAt": "2026-10-20T14:00:00.000Z",
    "purpose": "Updated class presentation"
  }
  ```
* **Success Status:** `200 OK`
* **Response Example:**
  ```json
  {
    "id": "ac987ead-cd6b-4e6d-9eae-360aa127dcba",
    "equipmentId": "eq-1",
    "borrowerName": "Somchai Jaidee",
    "startAt": "2026-10-20T12:00:00.000Z",
    "endAt": "2026-10-20T14:00:00.000Z",
    "purpose": "Updated class presentation"
  }
  ```
* **Validation & Error Responses:**
  * `404 Not Found` (Booking `:id` does not exist):
    ```json
    { "error": "Booking not found" }
    ```
  * `400 Bad Request` (Empty payload `{}` or no valid fields):
    ```json
    { "error": "At least one field must be provided for update" }
    ```
  * `400 Bad Request` (Updated `startAt >= endAt`):
    ```json
    { "error": "startAt must be before endAt" }
    ```
  * `404 Not Found` (Target `equipmentId` does not exist):
    ```json
    { "error": "Equipment not found" }
    ```
  * `409 Conflict` (Updated interval conflicts with another booking on same equipment):
    ```json
    { "error": "Booking time conflicts with an existing booking" }
    ```
  * *Note:* Self-updates do not trigger false conflicts because the target booking itself is excluded (`AND id != ?`).

---

### `DELETE /bookings/:id`
* **Purpose:** Cancel and remove a booking.
* **Request Body:** None
* **Success Status:** `204 No Content` (Empty response body)
* **Error Status:**
  * `404 Not Found` (Booking not found or already deleted):
    ```json
    { "error": "Booking not found" }
    ```

---

## 4. Business Rules & Overlap Logic

### Overlap Detection Rule
Two bookings for the **same equipment** are considered overlapping if and only if:
```text
existing.startAt < requested.endAt
AND
existing.endAt > requested.startAt
```

* **Adjacent bookings are permitted:** If Booking 1 ends at `11:00` and Booking 2 starts at `11:00`, `11:00 > 11:00` evaluates to `false`. They do not conflict.
* **Concurrent bookings across different equipment are permitted:** Overlap logic is strictly scoped to `WHERE equipmentId = ?`.
* **Parameter Binding:** Every query is executed using parameterized SQL placeholders (`?`) via D1 `.bind(...)`. User input is never concatenated into SQL strings.
